# 星塔旅人抽卡记录工具

## 软件是做什么的

这是一个面向《星塔旅人》Windows 客户端的非官方抽卡记录整理工具，可自动识别 `xtlr.exe` 和 `StellaSora.exe`。当前仍使用内置中文名称和卡池资料；进程识别不代表已验证所有海外客户端的 UID、招募记录和卡池规则兼容性。

软件可以读取并保存四类招募记录：

- 旅人限时招募
- 秘纹限时招募
- 旅人常驻招募
- 秘纹常驻招募

界面会统计总抽数、五星数量、当前垫抽和五星间隔。限时卡池会按具体卡池展示官方名称、活动时间、实际抽数，以及五星结果的 `UP` 或 `歪`。历史记录会持续合并到本地归档，不会因为官方只保留近期记录而主动删除旧数据。

旅人限时池单期累计满 120 抽时，首页卡池详情和五星招募记录会在该期角色前展示一个当期 UP 的“井”奖励。每期最多展示一个，换期重新计数；该奖励仅用于展示，不计入抽卡统计，不重置垫抽，也不会写入或上传到 JSON 归档。展示依据已保存的该期记录，历史记录不完整时可能无法显示。

## 怎么实现的

软件通过 Windows `ReadProcessMemory`，只读访问游戏客户端当前已经加载到 Lua 运行时中的招募历史。

- 不抓包，不运行本地代理服务器。
- 不注入 DLL。
- 不修改游戏文件或游戏内存。
- 不模拟点击，不发送游戏协议请求。
- 每次读取时动态查找 Lua 数据，不依赖固定内存地址。

读取结果会整理为本地 JSON/CSV，并按当前游戏 UID 合并保存到 `exports/UID.json`。角色与秘纹头像只用于本地界面展示。

## 使用流程

1. 启动并登录《星塔旅人》，进入游戏主界面。
2. 在游戏中依次打开四类招募记录，并等待每个记录列表显示出来。

![依次打开四类招募记录](docs/images/gacha-history-menu.png)

3. 双击本工具，确认 Windows 管理员授权提示，再点击“刷新游戏数据”。只运行一个客户端时自动读取；多个客户端同时运行时，根据程序位置和 PID 选择本次读取的客户端。软件会读取该进程中的当前 UID，生成对应的 `UID.json`。
4. 等待读取完成，在首页和“招募记录”页面查看结果。
5. 如需同步到蕾姆，点击“上传抽卡记录到蕾姆”。同一 UID 在本地首次上传成功时弹出 `星塔抽卡绑定 UID` 指令；以后不再弹出，可在设置中复制。
6. 新角色和秘纹图片会随软件版本内置更新；发现新版本时使用“检查更新”。

游戏不会在登录时一次性加载全部招募历史。未在游戏内打开的分类可能无法读取，软件会在界面中显示当前已加载的分类数量。

## 使用建议

- 每次产生新抽卡记录后，先在游戏中打开对应分类的招募记录，再刷新软件数据。
- 归档按完整 UID 隔离，不按 UID 的首位数字判断区服；读取不到 UID 或检测到多个 UID 时会停止，不会沿用旧账号写入。
- 打包版启动时自动请求管理员权限，取消授权会退出。源码运行不自动提权；命令行默认自动识别客户端，多开时可通过 `--pid` 指定，`--process` 可限定进程名。
- 建议定期使用设置页面的“创建备份”，或者手动备份 `exports/UID.json`。
- 官方记录可能只保留最近半年。本地归档可以保留更早记录，但必须在官方记录过期前至少读取并保存一次。
- 统计结果只基于当前已经读取并归档的数据。若早期记录缺失，首个五星的间隔和当前垫抽可能不完整。
- 安装版适合日常使用；便携版移动时应将整个程序目录和 `exports` 数据一起保留。
- 上传接口只暂存完整归档，成功后仍需发送绑定指令；软件不会上传 Cookie、密码或 QQ 信息。
- 首次上传状态按 UID 保存在本地 `exports/rem_upload_state.json`，重启软件仍然有效，上传失败不会记录。它不是服务器绑定状态；现有接口每次上传仍需给蕾姆发送绑定指令确认正式更新。
- 升级后的首次读取会将旧归档迁移到当前 UID，请先确认旧归档属于当前账号；旧文件会保留。之后切换账号不会再合并旧归档。
