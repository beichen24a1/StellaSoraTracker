## 下载 Windows 版本

### Electron 桌面版

当前源码默认使用 **Vue 3 + TypeScript + Electron**，通过本地 JSON Lines 接口复用 Python 抓取、归档、防串号和上传逻辑。左侧导航为「主页 / 招募总览 / 招募记录 / 好感度 / 角色 / 活动日历 / 数据与设置 / 上传与分享 / 使用说明」，只有白/黑两种主题；首次默认白色，旧 A 映射黑色、旧 B/C 映射白色，选择保存在 `color_mode`，不覆盖旧主题字段。今日运势入口已移除。

### 主页

启动后进入主页，汇总当前账号的招募统计、近期五星、角色与好感度缓存，以及国服活动日程，并提供原有功能的入口。招募总览仍独立保留；主页不自动读取游戏内存或上传记录。没有读取过的模块显示空状态，活动概览使用已保存的日历，进入活动日历可刷新官网数据。

### 活动日历（当前源码）

参考 [AUTO-MAS](https://github.com/AUTO-MAS-Project/AUTO-MAS) 的 MSS 活动页交互，自行实现活动主视觉、常驻活动、可滚动日程、状态筛选、倒计时和官网公告跳转。页面只有**国服**活动数据，来源为[星塔旅人国服官网](https://stellasora.yostar.cn/)，独立于当前账号和服务器选择；所有时间按北京时间（UTC+8）显示。维护后开放且未公布准确时间的活动会明确标注，规则和奖励以官方公告为准。

首次进入页面会读取官网公告，之后优先使用 15 分钟内缓存，也可手动刷新。活动与封面保存在 `exports/calendar/`，断网时保留上次日历；仅保留近期结束的活动，不支持完整历史查询。页面不会执行游戏任务，也不会向官网上传账号或抽卡数据。实现未引入 AUTO-MAS 源码，项目代码继续采用 MIT；活动图片和公告内容权利归各自权利人。

更新界面增加可滚动的更新说明、下载进度/速度/剩余时间、后台下载、取消、重试和稍后安装；已校验的更新包在重启后重新核验再恢复。任务与日志从底部状态栏打开，上传地址和归档原文不进入日志。完整迁移对照见 [功能对照表](docs/electron-parity.json)。

开发环境需要 Node.js 22.12+、Python 3.10+；运行 `python -m pip install -e ".[dev]"` 后，用 `./run.ps1` 构建并打开新客户端。首次会通过 `npm ci` 安装前端依赖。渲染器热更新可另起 `frontend` 中的 `npm run dev`，通过 `VITE_DEV_SERVER_URL` 连接；正式程序只加载本地打包页面。

本地验收构建：`./build_electron.ps1`（或 `./build_release.ps1`），输出 `release/StellaSoraGachaTool-Electron-local-win64.zip`，不会更新正式版本号、发布清单或 tag。包内自带 Python 核心和 Electron 运行时，**不需要用户安装 Python，也不携带 PySide6 界面运行库**。主程序清单要求管理员权限：双击 `StellaSoraGachaTool.exe` 会弹出一次 UAC，确认后直接可用；数据仍在程序旁的 `exports`。

验证命令：`./.venv/Scripts/python.exe tools/run_tests.py`；前端目录执行 `npm test`、`npm run test:e2e`。冻结包与中文路径验收工具为 `tools/verify_electron_package.py`，会复制包到独立目录，并校验客户端清单要求管理员权限、引擎与署名文件随包提供。

## 启动方式

解压后双击 `StellaSoraGachaTool.exe`，Windows 会弹出一次 UAC，确认后以管理员身份启动。读取游戏内存需要管理员权限，所以启动即授权，没有单独的启动器。

程序会在自己的目录写入 `exports` 和 `.desktop`，请放在有写权限的位置（例如桌面或 `%LOCALAPPDATA%`），不要放在 `Program Files` 下。

### 旧版更新后无法启动

如果出现“Windows 无法访问指定设备、路径或文件”，先保留旧程序目录和整个 `exports`，将完整 ZIP 解压到一个有读写权限的**全新目录**，再复制旧 `exports`。旧更新器留下的权限问题可能随原目录保留，完整的新目录可避免继续继承这些权限。

从 b3 开始使用校验后的下载包内更新器，检查程序目录和运行库对普通用户的访问权限；Windows 拒绝启动新程序时恢复旧文件并保留下载包。更新完成后的临时清理失败只记日志，不再误报整次更新失败。已安装旧客户端仍可能先执行自己的旧更新器，首次迁移建议完整解压到新目录。若仍被拒绝访问，请记录原版本、目标版本和更新方式，并保留 `%LOCALAPPDATA%/StellaSoraGachaTool/logs/updater.log` 供排查。

b4 增加旧安装权限修复和提权重启兼容：权限修复只处理本次更新包管理的损坏程序条目，保留安装目录、用户数据与健康文件的自定义权限，并跳过 junction 等链接目标。


`1.3.0.bata2` 是首个 Electron 测试版；历史 `1.3.0.bata1` 保留为 Qt 客户端，原有发行资产不变。

## 自动上传与软件更新

在「数据与设置 → 自动上传与更新」控制两个独立开关，选择会随主题偏好一起保存在 `exports/ui_settings.json`，切换主题或账号后仍然有效。

- **自动上传（默认关闭）**：成功抓取或导入记录后，将对应 UID 的完整归档上传到蕾姆。使用与某一文件一致的接口 `喵喵喵`，不需要登录或 Token。上传地址内置固定、不在界面显示，无需也不能填写。按账号记录成功指纹，未变化的归档不重复上传；上传失败不会改动本地归档，下次抓取或导入时可再次尝试。关闭后仍可在「上传与分享」手动上传。
- **自动更新（默认开启）**：Windows 发行版启动时检查更新，没有每 6 小时定时检查。发现新版先询问是否下载，完成 SHA-256 校验后再询问是否重启安装；抓取或上传进行时会等待空闲。关闭开关会停止自动检查、取消自动下载及待安装提示，手动检查不受影响。源码模式不自动更新。发行更新统一指向本仓库的 GitHub 清单，可通过环境变量覆盖。

上传成功表示归档已暂存，**每次仍需向蕾姆发送「星塔抽卡绑定 UID …」指令确认正式更新**；指令显示在「上传与分享」中。自动上传不会代发绑定指令。

开发验证：`./.venv/Scripts/python.exe tools/run_tests.py`；前端目录执行 `npm test` 和 `npm run test:e2e`。Python 核心及测试不依赖 Qt。

## 界面主题

Electron 版仅提供白色和黑色，主题在“数据与设置”切换并记忆；页面、导航、弹窗和任务面板带过渡动画，遵循系统“减少动态效果”设置。记录页以头像和五星间隔条展示紧凑的卡池历史，保留一列、两列和自动排布。

## 软件是做什么的

功能取舍按 [人工判断记录](docs/integration-decisions.json) 实施，引用的上游文件和原始哈希见 [上游来源记录](docs/upstream-imports.json)。本测试版已整合 A 的左侧导航、B 的 `exports/<UID>.json` 主归档结构、后续 UID 修复与仓库审查修复；保留当前绑定提示方案。发行形式为免安装 ZIP，许可证为 MIT。

### 归档与兼容

- `exports/<UID>.json` 是主归档，同时用于分享和上传；`accounts.json` 保存账号清单与选择。
- `exports/accounts/<账号>/` 保留独立 UID 配置、上传成功标记、时间戳导出和旧档。迁移按 UID 校验、合并去重，保留原文件；无 UID 的旧档单独保存，不自动认领。
- 迁移、导入、抓取保存和账号修改使用跨进程事务锁，避免多窗口覆盖记录；异常归档分类停止写入。
- 删除账号将其目录和主归档移到保留目录；同 UID 仍有其他账号时保留共享主归档。建议始终备份整个 `exports`。
- 名称缓存按语言隔离，秘纹补全保留正确类别；周年和常驻池不显示“UP/歪”。

测试版检查独立的 `app_update_beta.json`，不会将稳定版用户自动切换到测试版。

## 读取与归档保护

- 多开客户端时按进程名、PID 和路径选择具体实例；命令行可组合 `--server tw --pid 1234`。台服 UID 适配已通过模拟内存测试，实际客户端兼容性仍需实机验收。
- 实际读取不沿用手填或旧 UID。读取前后必须确认唯一 UID 及同一游戏进程启动时间；同一启动会话内切号或出现歧义会写入阻断标记，重启工具不能解除，需要重启游戏。
- 保存和上传前检查其他 UID 的异常重复记录。已有归档不能仅凭手填 UID 重新归属，也不能合并不同 UID 或归属未确认的旧档。
- 无 UID 的旧档保留在原位置及默认账号目录，不自动并入新读取的 UID。主归档损坏时停止保存；先备份整个 `exports`、核对 UID，再恢复 `<UID>.json` 后重新读取。旧版的账号目录归档继续保留。
- 周年特选使用原始分类 `6`，在抓取、导入、CSV、合并、分享和上传中保留；界面把它归入「活动卡池」，不再单独占一个分类。上传服务是否接受分类 `6` 需要单独联调。
- 招募总览的 UP 保底进度与记录页两次五星间隔分别计算；普通旅人限时池的 120 抽奖励只参与展示，不改归档、抽数或五星统计。

这是一个面向《星塔旅人》Windows 客户端(国服、国际服与日服)的非官方抽卡记录整理工具。

软件可以读取并保存游戏提供的招募记录，界面展示四类常规卡池和活动卡池：

- 旅人限时招募
- 秘纹限时招募
- 旅人常驻招募
- 秘纹常驻招募
- 活动卡池（含周年特选；周年特选原始分类 `6`，卡池 `1001`）

界面会统计总抽数、五星数量、当前垫抽和五星间隔。限时卡池会按具体卡池展示官方名称、活动时间、实际抽数，以及五星结果的 `UP` 或 `歪`。活动卡池单独统计：它的抽数和五星只出现在「活动卡池」里，不并入四类常规卡池的抽数、五星、垫抽或 `UP` 平均；顶部「账号累计」仍然包含活动卡池。历史记录会持续合并到本地归档，不会因为官方只保留近期记录而主动删除旧数据。

### 好感度

左侧导航的「好感度」是独立的一页，有自己的「读取好感度」按钮，数据也单独存放：

- 每个旅人显示好感等级、当前经验和升级所需经验（例如 `小禾 Lv.65 6040 / 33100`），以及是否收藏；
- 四星、五星角色的头像都随版本内置（`assets/travelers/<角色ID>.png`），不用联网也能显示；
- 升级所需经验取自游戏自带的好感等级配置表，等级或上限变化后不需要改代码；
- 读取结果按 UID 单独保存为 `exports/<UID>_affinity.json`（读取不到 UID 时是 `unverified_affinity.json`），与 `exports/<UID>.json` 抽卡归档完全分开，不会混进或改动抽卡数据；
- 页面会显示这份数据对应的 UID，切换账号后各看各的；
- 只读内存、随时可刷新，与抓取/上传互不阻塞；游戏没开时页面显示上次保存的结果；
- 读取需要管理员权限并保持游戏已登录，游戏没运行时按钮会提示找不到客户端。

命令行对照：`python tools/probe_affinity.py`（加 `--json` 便于粘贴）。

### 角色数据

左侧导航的「角色」是独立的一页，读取等级、突破、技能等级、天赋和纹章：

- 每位旅人显示等级、突破阶段、5 个技能等级、天赋已激活节点数（例如 `11 / 50`）和命运天赋层数；
- 纹章按 3 个槽位显示（尖章 / 方菱章 / 星闪章，分别需要角色 70 / 80 / 90 级解锁），包含名称、类型、强化次数、随机属性和词条数量；
- 随机属性名、词条名和天赋名称/描述取自游戏自带的配置表（`UIText` / `Talent`），属性按配置行的枚举值翻译，配置读不到时退回显示原始 ID；
- 天赋与纹章分别来自 `PlayerTalentData._tbCharTalentNode` 和 `PlayerEquipmentData.tbCharEquipment`，读取方式是只读内存、按字段名动态定位，不依赖固定地址；
- 读取结果按 UID 单独保存为 `exports/<UID>_roster.json`（读取不到 UID 时是 `unverified_roster.json`），与抽卡归档、好感度文件互不影响；
- 页面显示数据对应的 UID，切换账号后只显示该账号缓存；尚未读取时显示空状态，不借用其他账号的数据。未绑定 UID 的账号只加载未确认缓存；游戏没开时仍可查看自己的已保存结果；
- 读取需要管理员权限并保持游戏已登录；第一次读取前请在游戏里打开一次「角色」和「纹章」界面，让客户端把对应数据加载进内存。

命令行对照：`python tools/probe_character.py`（结构探针，只读，输出 `build/character_probe.json`）。

## 怎么实现的

软件通过 Windows `ReadProcessMemory`，只读访问游戏客户端当前已经加载到 Lua 运行时中的招募历史。

- 不抓包，不运行本地代理服务器。
- 不注入 DLL。
- 不修改游戏文件或游戏内存。
- 不模拟点击，不发送游戏协议请求。
- 每次读取时动态查找 Lua 数据，不依赖固定内存地址。

读取结果会整理为本地 JSON/CSV，并合并保存到 `exports/<UID>.json`。老版归档会复制合并迁移，原文件保留；没有 UID 的旧档保留在独立目录。角色与秘纹头像只用于本地界面展示。以上目录说明针对当前源码，v1.3.0 使用旧目录。

## 使用流程

0. 不需要手动选择服务器: 工具自动检测运行中的客户端(国服 `xtlr.exe`；国际服与日服共用 `StellaSora.exe`)。
   - 恰有一个客户端在运行且只对应一个版本 → 自动识别并读取;
   - 国服与 `StellaSora.exe` 同时运行 → 点击“抓取抽卡记录”时弹窗让你选择本次要读取的服务器;
   - **国际服与日服共用同一个客户端**, 进程名区分不出来 → 在「设置 → 游戏版本」点一次「日服」即可(会记住);
   - 「设置 → 游戏版本」可随时手动指定(保存到 `server.json`), 卡池名/角色名/UP 判定按所选服务器的语言显示(简中 / 英文 / 日文)。

2. 在游戏中依次打开需要读取的招募记录（包括周年特选），并等待每个记录列表显示出来。

3. 以管理员身份运行本工具，点击“抓取抽卡记录”。

## 导入其他来源的记录

「导入数据」除了本工具导出的 JSON/CSV，也能直接读取网页版与分享链接下载的归档文件。后者是带外壳的格式：

```json
{
  "version": 1,
  "uid": "100872990",
  "updatedAt": "2026-10-12T07:18:09.124641+00:00",
  "categories": { "1": [], "2": [], "3": [], "4": [] }
}
```

- 记录按官方分类完整保留（1 旅人限时 / 2 旅人常驻 / 3 秘纹限时 / 4 秘纹常驻 / 6 周年特选）；界面把分类 `6` 归入活动卡池展示。未知分类会停止写入并保留原档，不再回退到 1 或 3。
- 导入的数据会合并进 `exports/<UID>.json` 并立即生效，之后再点「抓取抽卡记录」也不会被游戏里的近期记录覆盖。合并按 `(Gid, Time, Ids)` 去重，同一个文件反复导入不会重复计数。
- `uid` 会被一直保留：导入带 `uid` 的文件后，本地归档和之后导出的 JSON 都会带上同一个 `uid`。
- CSV 没有分类列时，工具按 `Gid` 反推每条记录属于哪一类；GB18030 编码的中文 CSV 也能读。

## 多账号

一个工具可以同时管理多个账号, 每个账号(UID)有**自己独立的记录**: 垫抽、保底与五星概率都是按账号算的, 混在一起就会全错。

- 目录结构: `exports/<UID>.json` 放该账号的主归档与分享数据；账号配置、旧档和时间戳导出保留在 `exports/accounts/<账号>/`；账号清单在 `exports/accounts.json`。
- 「设置 → 账号」下拉框切换当前账号; 也可「新建账号」「重命名」「删除」(删除只是把目录改名为 `<UID>.deleted_<时间>` 保留数据, 不会真删)。
- **自动归位**: 切换游戏账号后必须先完全退出并重启游戏，再抓取记录。通过 UID 复核后工具切到对应账号（没有就新建）；同一次游戏启动中检测到切号会停止保存。导入带 UID 的分享文件也按归属校验后归位。
- 老版本(单账号)的数据会在首次启动时自动迁移成一个账号(以归档里的 UID 命名), 原文件保留不删。

## 使用建议

- 每次产生新抽卡记录后，先在游戏中打开对应分类的招募记录，再刷新软件数据。
- 建议定期使用设置页面的“创建备份”，或者备份整个 `exports`（包含 `<UID>.json`、账号配置和旧档）。
- 官方记录可能只保留最近半年。本地归档可以保留更早记录，但必须在官方记录过期前至少读取并保存一次。
- 统计结果只基于当前已经读取并归档的数据。若早期记录缺失，首个五星的间隔和当前垫抽可能不完整。
- 移动免安装版时，应将整个程序目录和 `exports` 数据一起保留。
