## 建议采用 MIT

这个项目以桌面工具、共同维护和方便用户分发为主，建议代码采用 MIT。MIT 允许使用、修改、再分发及商业使用，分发副本或实质部分时需要保留版权声明和许可文本；它不要求修改后的代码必须公开。见 [MIT 原文](https://opensource.org/license/mit)。

两份来源仓库目前没有明确开源许可证。GitHub 公开可见、可以 fork，不等于已获得任意再许可的权利，见 [GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。因此要先确认原作者及相关权利人同意将其贡献以 MIT 授权，再写入正式 LICENSE。

现有 README 有“不要用于商业用途”的表述，pyproject.toml 有“Private research tool”占位说明；若最终采用 MIT，需同步调整这些冲突表述。若希望禁止别人商业使用，MIT 不适合，不能仅加一句禁止商用却继续宣称标准 MIT。

MIT 的决定只针对有权授权的项目代码和文档。游戏角色、秘纹图片以及外部资料应单独标注来源和适用权限，不会因为项目使用 MIT 就自动以 MIT 授权。

## 卡池表和头像资源

**卡池表**是“卡池 ID → 名称、所属招募类型、开放时间、UP 名单”等对应资料。当前程序有内置兜底表，也会读取 StellaBase 的在线资料并缓存，切换服务器时使用相应语言。它用于显示卡池名称、活动日期、UP/歪等信息，不是用户的抽卡记录。

**头像资源**是结果列表、卡池卡片等位置显示的旅人和秘纹小图（PNG），通过角色或秘纹 ID 对应；不是用户自己的账号头像。名称目录还提供名称和稀有度信息。

“核对卡池表与头像资源”指检查新旧两份资料有无缺项、同一 ID 是否对应不同内容、图片能否读取，以及服务器/语言是否匹配。程序可以继续自动补全新资料；缺图时应使用占位显示，不能为了补图改动用户抽卡结果。这个核对项属于可由开发继续处理的技术工作，无需用户逐张确认；出现真实冲突再列出具体选项。
